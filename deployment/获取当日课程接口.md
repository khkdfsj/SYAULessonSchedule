# 获取当日课程接口



---

## 基本信息

| 项目 | 内容 |
|---|---|
| 请求URL | `https://debug.91nongye.cn/LessonSchedule/getTodayCourse.php` |
| 请求方法 | `POST` |
| Content-Type | `application/json` |

## 功能说明

根据学号查询该学生**当天**（或指定星期/教学周）的课程。自动过滤教学周，精确到每节课的起止时间，含夏季/冬季作息表自动切换。

**日期计算逻辑**：
- 自动模式（不传 currentWeek）：取当天日期，targetDayOfWeek 可在本周内偏移
- 手动模式（传入 currentWeek）：根据自动推断的开学日 + (周次-1)×7 + (星期-1) 精确计算目标日期，作息表也随目标日期切换

返回结构化 JSON 数据 + 预格式化的**纯文本消息**，专为**企业微信应用消息**设计——机器人可将 `textMessage` 或 `quickText` 字段直接作为 text 类型消息的 Content 被动回复给用户。

## 请求参数

```json
{
    "UserID": "2025192052",
    "currentWeek": 12,
    "targetDayOfWeek": 3
}
```

| 参数 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| `UserID` | string | 是 | 纯数字，长度 1-20 | 学生学号 |
| `currentWeek` | int | 否 | 1-25 | 当前教学周。不传则自动计算。传入时接口会据此计算目标日期并切换对应作息表 |
| `targetDayOfWeek` | int | 否 | 1-7（1=周一，7=周日） | 指定查询星期几。不传则取当天 |

## 响应结构

### 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 业务状态码，200 表示成功 |
| `msg` | string | 操作提示信息 |
| `apiVersion` | string | API 版本号，遵循语义化版本规范 |
| `requestId` | string | 请求追踪ID，格式 `YYYYMMDDTHHmmss-随机6位`，用于问题排查 |
| `elapsedMs` | int | 接口总耗时（毫秒），含远程调用时间 |
| `data` | object | 响应数据体，错误时为 `null` |

## 消息格式说明

`textMessage` 和 `quickText` 字段均为**纯文本格式**，符合[企业微信应用消息 text 类型](https://developer.work.weixin.qq.com/document/path/90241#文本消息)规范，最长不超过 2048 字节。

### 格式排版

使用纯文本符号进行排版美化：

| 符号 | 用途 | 示例 |
|---|---|---|
| `━`（重复20次） | 分隔线，区分头部和内容 | `━━━━━━━━━━━━━━━━━━━━` |
| `【1】【2】` | 课程编号，醒目易识别 | `【1】分析化学（Ⅰ）` |
| `  时间  ` `  地点  ` | 字段对齐，便于阅读 | `  时间  10:00-11:40` |
| `⚠` | 警告标识（仅警告信息使用） | `⚠ 开学日为自动推断...` |

### textMessage 与 quickText 的区别

| 字段 | 定位 | 信息密度 | 适用场景 |
|---|---|---|---|
| `textMessage` | 完整版 | 高（含课程名、时间、地点、教师、学分、周次） | 用户主动查询课程详情 |
| `quickText` | 精简版 | 低（仅课程名、时间、地点） | 推送通知、列表预览 |

### 字节长度限制

企业微信应用消息 text 类型 Content 最长 2048 字节（UTF-8 编码）。当前课程量下不会超限。

## 教学周自动计算说明

### 算法原理

接口采用**两级策略**自动计算当前教学周：

**当课程数据可用时（精确模式）**：
1. 根据当前日期判断学期：2~7月为春季学期，8~次年1月为秋季学期
2. 在对应学期的"搜索窗口"内遍历每个周一，作为候选开学日
3. 对每个候选开学日，计算当前日期对应的教学周
4. 对每个候选教学周，统计**全部课程**（不限当天星期几）的匹配数量作为评分
5. **过滤**：保留评分接近最高分的候选（差值不超过3），消除明显不合理的候选
6. **排序**：在合理候选中，优先选择距搜索窗口中心最近的候选；同距离时评分高者优先
7. 取排名第一的候选作为开学日期，据此计算教学周

**邻域评分（平滑假期等间隙周）**：

为避免因法定节假日、调课或课程自然分布不均导致的评分波动，主评分采用**邻域匹配**策略：

- 对每个候选教学周 `W`，统计在 `[W-N, W+N]` 范围内（N = `SEMESTER_START_NEIGHBORHOOD_SIZE`）**有课**的课程数量作为主评分 `score`
- 同时记录精确匹配数 `exactScore`（仅当前周 `W` 有课的课程数）作为参考
- 默认 `N=1`，即检查 `[W-1, W, W+1]` 三周内是否有课

**示例**：若某课程在 1-9, 11-17 周上课（第10周为假期），当候选周 `W=10` 时：
- 精确匹配 `exactScore`：该课程不计入（第10周无课）
- 邻域匹配 `score`：该课程计入（第9周、第11周有课）

这样即使当前周正好处于假期周，算法仍能正确识别该候选为"有效教学周"，避免误判。

**候选过滤策略（消除学期末评分偏向）**：

仅按评分排序存在一个缺陷：学期末课程密度自然下降时，更晚的开学日（对应更早的教学周）会因剩余课程较多而获得更高评分，导致误判开学日期延后。算法采用两阶段决策：

1. **评分过滤**：计算所有候选的最高分 `maxScore`，保留评分 ≥ `max(maxScore - 3, 1)` 的候选，剔除明显不合理的低分候选
2. **窗口中心优先**：在保留的合理候选中，按开学日期距搜索窗口中心的距离升序排序；同距离时评分高者优先

**窗口中心优先策略**：
- 窗口中心 = 搜索起止日期的中点（如春季窗口 2/20~3/10，中心约 3/1）
- 基于北方大学开学日期集中分布在窗口中部附近的统计规律
- 在评分相近的候选中，优先选择统计上最可能的开学日期，避免学期末课程密度下降导致的误判

**当课程数据不可用时（回退模式）**：
1. 使用配置的默认开学日期（春季3月1日，秋季9月1日）
2. 自动对齐到该日期所在周的周一
3. 计算教学周并附偏差警告

### 搜索窗口配置

基于北方大学开学规律定义搜索范围，算法在此窗口内智能匹配：

```php
// 春季开学搜索窗口：2月20日 ~ 3月10日
define('SPRING_SEARCH_START', '02-20');
define('SPRING_SEARCH_END', '03-10');

// 秋季开学搜索窗口：8月20日 ~ 9月10日
define('FALL_SEARCH_START', '08-20');
define('FALL_SEARCH_END', '09-10');
```

### 邻域匹配配置

```php
// 开学日检测：邻域匹配窗口大小（±N周）
// 在当前教学周前后各N周范围内统计有课的课程数，用于平滑假期等间隙周导致的评分波动
// 值为1时表示检查 [当前周-1, 当前周, 当前周+1] 三周内是否有课
define('SEMESTER_START_NEIGHBORHOOD_SIZE', 1);
```

### 回退默认日期

仅当上游课程数据不可用时使用：

```php
define('SPRING_FALLBACK_MONTH', 3);  // 春季回退：3月
define('SPRING_FALLBACK_DAY', 1);    // 3月1日（自动对齐该周周一）
define('FALL_FALLBACK_MONTH', 9);    // 秋季回退：9月
define('FALL_FALLBACK_DAY', 1);      // 9月1日（自动对齐该周周一）
```

### 学期间隙智能回退

- 当前日期处于春季开学之前 → 自动回退到上学期（秋季）计算假期/期末周次
- 当前日期处于秋季开学之前 → 自动回退到上学期（春季）计算假期/期末周次
- 标注"学期末/假期中"警告，提示周次为估算值


### 当前学期识别规则

| 月份 | 学期 | 学制 |
|---|---|---|
| 2月 ~ 7月 | 春季学期 | 第二学期 |
| 8月 ~ 次年1月 | 秋季学期 | 第一学期 |

### 精确性说明

- 课程数据充足时，算法可**精确识别**开学日期和教学周，无需每学期修改代码
- 评分基于**全部课程**（不受限于查询当天），即使当天无课也能利用其他日期的课程数据
- 邻域评分（±N周）可平滑假期周、调课等导致的评分波动，提升开学日识别稳定性
- 采用"评分过滤 + 窗口中心优先"两阶段决策，避免学期末课程密度下降导致的开学日误判
- 手动传入 currentWeek 时，接口仍会自动推断开学日，用于精确计算目标日期和切换作息表
- 未涵盖因法定节假日调课导致的周次偏移
- 调用方可通过 `currentWeek` 参数手动指定教学周，接口据此计算目标日期并切换对应作息表

## 设计特性

| 特性 | 说明 |
|---|---|
| 双作息表 | 夏季/冬季自动切换（5/1、10/1），基于目标日期而非当天，精确到每节课 |
| 日期计算 | 手动传入 currentWeek 时，根据开学日 + (周次-1)×7 + (星期-1) 精确计算目标日期 |
| 教学周计算 | 优先手动传入；未传入时基于课程数据在搜索窗口内精确匹配，采用"评分过滤 + 窗口中心优先"两阶段决策自动识别开学日并计算教学周 |
| 邻域评分 | 主评分采用 ±N 周邻域匹配，平滑假期等间隙周导致的评分波动，提升开学日识别稳定性 |
| 机器人消息 | textMessage/quickText 使用纯文本格式，符合企业微信应用消息 text 类型规范，可直接被动回复 |
| 链路追踪 | 每次请求生成唯一 `requestId`，便于定位问题 |
| 容错重试 | 远程 API 支持超时控制 + 自动重试 1 次 |
| 日志脱敏 | 请求日志按天存储，学号自动脱敏（如 `2025****052`） |
| CORS 支持 | 允许跨域访问 |
| 版本控制 | 响应附带 `apiVersion`，未来不兼容变更时调用方可适配 |

## 依赖

本接口依赖上游 API：`curlGetSyauInfo.php`，通过学号获取学生全部课程数据。

| 依赖项 | 地址 |
|---|---|
| 上游课程 API | `https://debug.91nongye.cn/LessonSchedule/curlGetSyauInfo.php` |
| 超时设置 | 连接超时 5s，整体超时 10s |
| 重试策略 | 失败后重试 1 次，间隔 500ms |
